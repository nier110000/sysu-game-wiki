# 最终复盘

这页将在 GameJam 结束后把观察、讨论、原型和成品连成一条完整记录。复盘的重点不是给项目打分，而是把下一次还能复用的判断留下来。

## 复盘结构

### 最初的设计假设

我们想通过什么能力、规则和关卡问题产生怎样的玩家行为？

### 从案例中借鉴了什么

链接到对应的观察表条目和 Wiki 案例，并说明哪些关系被保留、哪些被主动删去。

### 原型如何变化

记录关键版本、试玩发现和方向调整。尤其保留“为什么没有继续做”的方案。

### 成品与玩家行为

预期解法、实际解法、意外解法分别是什么？玩家在哪里理解或误解了系统？

### 制作复盘

- 设计：范围和验证方式是否合适？
- 程序：哪些临时实现需要重做或可以沉淀？
- 美术：信息传达和反馈是否支持玩法？
- 协作：哪些沟通节点有效，哪些造成返工？

### 下一次会怎样做

写出三条可以执行的改变，而不只写“提前规划”“加强沟通”。
