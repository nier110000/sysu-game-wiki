# 2D 原型提案

第 11 个观察问题是整个流程的出口：**如果简化为小型 2D 游戏，会保留什么能力、动作和关卡问题？**

## 提案模板

```md
# 原型名

## 一句话假设
如果玩家可以 ______，那么在 ______ 的限制下，会产生 ______ 的不同解法。

## 核心能力

## 三条以内的基础规则
1.
2.
3.

## 最小关卡问题

## 至少两种预期解法

## 暂时不做

## 需要观察的玩家行为

## 成功标准
```

## 原型约束

- 先用基础图形和占位音效完成灰盒。
- 只保留验证设计假设所需的能力和对象。
- 一个试玩回合尽量控制在 5 分钟内。
- 原型必须能观察玩家行为，而不仅是展示开发完成度。
- 记录测试者首先尝试什么、在哪里误解规则、是否发现非预设解法。

## 评审问题

1. 这个原型验证的是哪个明确问题？
2. 去掉一个规则后，核心体验是否仍然成立？
3. 玩家是否能从反馈中推断规则？
4. 关卡是否真的支持多解，还是只有一种正确答案和一种漏洞？
