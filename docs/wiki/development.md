## 我们记录什么

- 可以复用的基础系统与项目结构。
- 原型阶段如何用最小成本验证玩法。
- 联机、物理、动画、UI 等模块的实现笔记。
- Git 分支、合并、构建与发布中的协作经验。
- 一次具体故障的原因、排查路径与最终修复。

## 原型优先

GameJam 的技术选择应服务于验证核心体验。先让最关键的动作和反馈成立，再扩展表现、内容与工程结构。每次原型结束后，把“哪些实现值得保留、哪些只是临时方案”写清楚。
